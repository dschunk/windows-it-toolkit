# SchunkOps 1.3.0 — Windows Server Operations

Released: 2026-09-20

SchunkOps 1.3 turns the module into a broader Windows Server operations toolkit while preserving the project's read-first, evidence-first approach.

## New commands

- `Invoke-SchunkServerAudit` — coordinates core server health, reboot state, service failures, event triage, listening ports, Windows Update health, and optional IIS/Hyper-V checks. Can write a self-contained HTML report.
- `Get-SchunkIisHealth` — sites, bindings, application pools, stopped-state summary.
- `Get-SchunkHyperVHealth` — host capacity, VM state, VHD/VHDX information, virtual switches, integration services, and aged checkpoints.
- `Get-SchunkSmbPermissionAudit` — SMB share access plus NTFS ACLs at each share root.
- `Test-SchunkGpoApplication` — GPResult evidence for computer and user policy without refreshing or changing policy.
- `Get-SchunkDnsServerHealth` — DNS zones, update configuration, replication scope, and forwarders.
- `Get-SchunkDhcpScopeHealth` — scope state, address utilization, and failover relationships.
- `Get-SchunkWindowsUpdateHealth` — pending updates, recent update history, and reboot evidence.

## Fast start

```powershell
Import-Module SchunkOps
Invoke-SchunkServerAudit -HtmlPath C:\Reports\server-audit.html
```

On an IIS or Hyper-V host:

```powershell
Invoke-SchunkServerAudit -IncludeIis -IncludeHyperV -HtmlPath C:\Reports\server-audit.html
```

Role-specific checks:

```powershell
Get-SchunkDnsServerHealth -ComputerName DC01
Get-SchunkDhcpScopeHealth -ComputerName DHCP01
Get-SchunkSmbPermissionAudit -Name Finance
Test-SchunkGpoApplication -Scope Computer
```

## Design rules

All new role diagnostics are read-only. The only intentional write in this release is the optional report file requested through `Invoke-SchunkServerAudit -HtmlPath`, which supports `-WhatIf`.

These commands are intended to produce inspectable PowerShell objects that can be formatted interactively, exported to JSON/CSV where appropriate, or consumed by automation.
