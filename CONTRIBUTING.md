# Contributing

Contributions that make the tools safer, clearer, more portable, or easier to operate are welcome.

## Before opening a pull request

1. Create a focused branch and keep the change narrow.
2. Test against a non-production system.
3. Preserve safe defaults and support ShouldProcess for consequential actions.
4. Return structured PowerShell objects where practical.
5. Add or update usage examples when behavior changes.
6. Run the repository's validation workflow.
7. Remove real hostnames, addresses, usernames, identifiers, credentials, tokens, and proprietary data.

## Pull request notes

Explain the operational problem, the approach, how the change was tested, required privileges, compatibility assumptions, failure behavior, and rollback considerations.

Security vulnerabilities should not be opened as public issues. Follow SECURITY.md instead.
